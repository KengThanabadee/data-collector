# Domain documentation

Data Collector uses one root `GLOSSARY.md` and one `docs/adr/` directory.

- Before naming a domain concept or proposing a design, read the glossary and relevant ADRs when they exist. Use the glossary's vocabulary in issues, code, tests and reviews.
- For v2 capture behavior and acceptance, read [SPEC.md](../../SPEC.md) and the relevant [collection scope](../v2/COLLECTION_SCOPE.md) or [acceptance gate](../v2/ACCEPTANCE.md). For v1 compatibility, read [the v1 specification](../SPEC_V1.md).
- Create glossary entries and ADRs as terms and decisions are resolved. Surface conflicts with an existing ADR and link it when reopening a decision.
